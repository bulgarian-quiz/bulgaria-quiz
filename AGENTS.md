# Project decisions

- Mobile map placement supports pointer-based drag plus tap-select fallback; desktop retains native drag-and-drop, because HTML5 dragging is unreliable on touchscreens.
- Standard navigation omits Home and overflow controls; mobile exposes the same destination and utility icons as desktop with unified Settings, so every action remains reachable.
- The standard site opens directly without a terminal gate; the school-logo footer button is the only standard-site entry into the desktop 3D experience, keeping mobile on the standard experience.
- Escape always exits the desktop 3D experience to the standard site and clears the forced game-mode address state; leaving it while the homepage is underneath lands on "Продължи пътешествието", not the film's start.
- In 3D game mode utility pages render inside the tablet via a MemoryRouter, while both games use native R3F scenes controlled by the shared experience store, so nothing leaves the 3D experience.
- Earth and vehicle media live under public textures/models, including the GLB's relative paint texture, so local and deployed scenes load identically.
- The standard homepage is one vertical scroll composition: handwritten Bulgaria reveal, 681–2026 horizontal history timeline, centered space-to-Bulgaria Earth approach, then a scroll-written closing message that reveals the standard toolbar; motion stays transform-based with reduced-motion handling.
- Interactive pages and dialogs share the journey palette and control styling through global semantic tokens and shared UI components, so the experience remains consistent without changing gameplay.
- The post-introduction homepage uses a non-overlapping Kinetic Noir mosaic component with route-driven tiles, because destination content must feel editorial without becoming a generic card grid.
- Desktop experience eligibility follows browser presentation mode and viewport width rather than pointer hardware, so “Request Desktop Site” works while touch controls remain available.
- Homepage film playback uses a cancellable time-based scroll animation with chapter/space phases and a shared journey destination, so Skip and the 40-second film end at the same section.
- All gameplay map targets use shared geoBoundaries province paths: RegionAtlas draws them in 2D (quiz and placement views) and src/experience/provinces3d.ts extrudes the same paths into 3D for the 3D-mode board and station hologram, so every map view agrees.
- The visual layer in src/atlas.css is Apple-style with black and white as the main colours: pure black and pure white themes (dark by default on every device, the visitor's choice from Settings remembered), the Apple system font (SF Pro) with Inter as the fallback, black-and-white photos, and Bulgarian-flag accents — red for actions, green for success and completed provinces — plus the red-and-gold shevitsa band as the single signature; the history film always stays dark. Colour, type and shape change there while index.css keeps motion and interaction rules.
- The 3D experience renders through one post-processing chain (bloom, ACES tone mapping, SMAA, vignette) with quality tiers driven by measured frame rate (Automatic/High/Low in the tablet), a loading overlay, and an error boundary with a way back to the site; its HUD and tablet use src/experience/experience.css (always dark, site fonts and accents), and Game 1's car falls back to a built-in model if the GLB cannot load.
- Search visibility comes from src/seo/routes.ts: the useSeo hook sets each route's title, description, canonical and JSON-LD in the app, and the build (vite.config.ts) writes a static HTML page per route with the same tags and readable content, plus sitemap.xml and a noindex 404.html; `base` stays "/" so nested routes load their assets.
- Game 1 stops by itself at each province's town sign (a planned, even braking distance), opens the questions automatically, moves on shortly after each confirmed answer and closes after the last one; shared drive state lives in src/experience/missionDrive.ts so the HUD speedometer reads it without React re-renders.
- Once the homepage film has been seen (watched, scrolled or skipped, remembered in localStorage), the toolbar's site title returns to "Продължи пътешествието" instead of the film's start; the homepage footer under the hub carries the same 3D-mode button as the other pages, and new pages open scrolled to the top.
- The AI chat runs through the chat edge function on a free keyless provider first (Pollinations), then the optional GEMINI_API_KEY free tier, with no paid fallback so it never bills; every visitor gets 10 messages an hour (per account, or per IP for guests), counted in the database by chat_rate_limit so it holds across function instances.
- First-time visitors get a bottom-right cookie banner (Accept/Reject, remembered, reopened from Settings → Бисквитки); on the homepage it appears once "Продължи пътешествието" is reached (scrolled into view, skipped to or the film ends) and then stays until a choice is clicked; it is portalled into <body> on the top layer so nothing can cover it. The site only uses necessary storage; anything optional must check hasOptionalCookieConsent() in src/lib/cookieConsent.ts first.
- Sign-up requires two checkboxes, agreeing to the Privacy Policy (/privacy-policy) and the Terms & Conditions (/terms-and-conditions), with the agreement time saved in the account's metadata; the URLs live in src/lib/legal.ts. Both pages are src/pages/Legal.tsx; the old /privacy and /terms addresses redirect to them.
- On the homepage the AI chat button (and its window and hint) waits for the same moment as the cookie banner, via the shared useAfterFilm hook (src/hooks/useAfterFilm.ts): once "Продължи пътешествието" is reached, skipped to or the film ends, and then stays for the visit; on other pages both show at once. Both use the toolbar's lightly translucent surface (.floating-glass in src/atlas.css).
- UI motion follows one "Premium" personality (src/index.css, "UI entrances, exits and feedback"): entrances use --ease-out over short distances with no overshoot, exits use --ease-exit at about two thirds of the entrance, transform and opacity only, with fade-only variants for reduced motion. Entrance animations use fill-mode "backwards" so none lingers on the translucent surfaces (a lingering animation switches off their backdrop blur).
- Scores are server-side: the browser cannot write user_stats; points, streaks, play time, flashcard counts and completed provinces go through the record_activity database function (src/lib/recordActivity.ts), which awards fixed amounts per action with hourly caps. Private multiplayer rooms are joined only through join_room_by_invite_code; the room helper functions answer only for the caller, and a trigger stops anyone changing a room's owner, invite code or game type or reopening it (supabase/migrations/20261112120000_secure_points_and_rooms.sql).
- The third game, "Познай мястото" (/photo-quiz, src/pages/PhotoQuiz.tsx), asks 27 photo questions (places, people, traditions) from src/data/photoQuestions.ts with photos at public/images/photo-quiz/NN.jpg (a numbered placeholder shows until one is added). It reuses the shared config screen with an Easy (four answers) / Advanced (typed) choice; the two modes are separate room types (photo, photo_typed) so matchmaking pairs players in the same mode. Typed answers are checked on the device first (src/lib/answerMatch.ts: case, articles, quotes, word order, typos, Latin letters), and only unconfirmed ones go to the check-answer edge function, which uses the chat's free providers under its own hourly limit and falls back to the device's verdict.
- The homepage history film's text (years, chapter titles and text, timeline, counter) is set in Segoe UI with system-font fallbacks (src/atlas.css, --font-history); Segoe UI cannot be shipped with the site, so non-Windows devices show their own system UI font. The opening handwritten "Bulgaria" signature stays in Caveat.
- Homepage scrolling stays light on phones: the Earth's 3D canvas mounts only within about two screens of its section (it no longer draws unseen during the history film), touch and small screens load earth-day-4k.webp instead of the 8K texture, only the history photo on screen is a GPU layer (will-change set inline), the film grain is unblended on touch devices, and scroll-driven sections measure against stableViewportHeight() (src/lib/viewport.ts) so iOS's address bar showing and hiding does not shift them.
- Names and profile photos are checked before they are saved: the browser cannot write display_name or avatar_url, which change only through the moderate-profile edge function (word list in supabase/functions/_shared/blockedWords.ts, then the chat's free text model for names; photos, shrunk to a 256 px JPEG, need Gemini's vision and are refused for now without it). An inappropriate one suspends the account for 24 hours (user_bans, supabase/migrations/20261124120000_profile_moderation.sql): BanScreen covers the site until it ends, and the server gives no points, rooms, chat or answer checks meanwhile; signing out removes the screen so shared school computers stay usable. Sign-up names are checked by the app first and by a database word list in handle_new_user; room player names always come from the profile.
